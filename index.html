📑 Technical Q&A Architecture Guide

The Old Way (Traditional Escrow)

Concept: A static bank vault.

Execution: Money sits in a database until a human support agent manually reviews chat logs, checks shipping receipts, and clicks a button to release funds.

[TRADITIONAL FLOW]
User Action ──► Human Review ──► Manual Database Update ──► Payout
The New Way (Our State Machine)

Concept: An event-driven logic engine.

Execution: The transaction moves through explicit states (e.g., INITIALIZED → PENDING_DELIVERY → INSPECTION → SETTLED). Transitions are triggered exclusively by API webhooks or chronological countdowns (Redis-backed timers).

[STATE MACHINE FLOW]
API Webhook / Timer Expiration ──► State Transition ──► Programmatic API Payout

Result: If a timer hits zero, the system executes a hardcoded default action automatically. 99% of transactions require zero human intervention, insulating operational margins as transaction density scales.

They are chronological logic gates. They prevent money from getting stuck in system limbo (float) and force counterparties to take action. Think of them as self-executing smart contracts governed by time.

Timer Variable Trigger Event Duration Parameters Programmatic Action on Expiration
TR_DELIVERY Buyer Payment Cleared 72h (Goods) / 120h (Services) Auto-cancels deal. Reverts 100% of funds to buyer wallet via API.
TR_INSPECTION Courier Webhook / OTP 24h (Goods) / 48h (Services) Auto-approves delivery. Fires the Payment Timer.
TR_REJECTION Buyer Logs a Dispute 48-Hour Buffer Freezes ledger slice. Routes payload to Dispute Triage API.
TR_PAYMENT Inspection Cleared Instantaneous Executes settlement payload to Partner Bank Open Banking API.

The Delivery Timer (TR_DELIVERY) is our **Pre-Delivery Safety Valve**. It is the only timer active immediately after payment authorization.

Its sole technical purpose is to kill abandoned transactions. If a seller ghosts the buyer and fails to provide a verified shipping update before this timer expires, the contract self-destructs.

Why this matters: It ensures we never exceed our 14-day absolute maximum system float. This keeps our partner bank ledgers perfectly clean and prevents buyer funds from being locked down by non-responsive sellers.

The TR_INSPECTION and TR_REJECTION timers are completely dead/inactive until the exact moment an authenticated delivery event is logged.

We do not rely on sellers clicking "I shipped it." We rely on direct third-party API integrations (such as a **GIG Logistics API** or **DHL Webhook**). When the courier inputs the One-Time Password (OTP) or delivery code at the buyer's doorstep, the logistics platform triggers a webhook payload directly into our state machine. That specific event-trigger instantly destroys the TR_DELIVERY timer and ignites the TR_INSPECTION timer.

When a buyer rejects an item, the state transitions to DISPUTE_TRIAGE and the TR_REJECTION timer triggers. To defend platform profitability, we isolate resolution workflows into a self-filtering hierarchy:

TIER 1 (GREEN)
Decentralized Chat

Counterparties have 72 hours inside a sandbox-isolated chat UI to select an auto-settlement template (e.g., partial refund or return). Zero internal admin hours spent.

TIER 2 (ORANGE)
Admin Recommendation

A platform arbitrator reviews the dispute logs and issues a Recommended Resolution. **Key Automation:** If users do not actively reject or pay to escalate, the recommendation auto-executes on expiry.

TIER 3 (RED)
Parametric Arbitration

Transacting parties must absorb an upfront escalation/arbitration fee to advance. This fee fully offsets our high-tier manual compliance and audit review operations.

TrustedPayer operates a strict **Non-Custodial Open Banking integration model**. We do not touch, hold, or store the fiat currency directly.

100% of transaction capital sits safely inside co-branded, ring-fenced nodal trust accounts at our commercial partner banks (e.g., Zenith Bank PLC). Our API backend functions as the absolute programmatic orchestrator.

When a settlement condition is met (like the TR_PAYMENT timer firing), our transaction ledger compiles a cryptographic payload. This payload instructs the banking infrastructure to run instant, intra-bank clearings to the verified merchant node.
